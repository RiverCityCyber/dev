Home Lab

PURPOSE

My home lab is where I learn and where I test new systems, services and automations before I rely on them. The network sits behind an OPNsense firewall with no inbound ports open, and a MikroTik switch splits it into three VLANs. Four machines share the work: an always-on small-form-factor server for core services, a Proxmox host I power on when needed, a Dell DL4300 for storage and backups, and a Mac mini for day-to-day development.

PRINCIPLES

I run and maintain the lab on a budget, guided by six principles:

  1. Least power needed
  2. Least access needed
  3. Full logging
  4. Automate where possible
  5. Document every step
  6. Smallest footprint possible

Together they keep the lab simple, secure and cheap to run. Power use and risk stay low while the services I depend on stay available. Wake-on-LAN lets hardware sleep until it's needed, and VPNs, PKI, MFA and intrusion prevention keep access smooth without loosening security.

NETWORK TOPOLOGY

HARDWARE

Following the first principle, I keep as few servers running as possible. Watching resource utilization shows whether a machine is constrained or sitting idle. I aim for 80–90% RAM use at all times and around 90% CPU use at peak load.

ALWAYS-ON SFF SERVER

This server runs everything that must stay available around the clock. To save resources it has no hypervisor: services run in Docker containers or as system services on Ubuntu Server, which I chose for its simplicity, reliability and broad support.

Tip: for any server running 24/7 with under 2 TB of storage, skip hard drives. NVMe is ideal, and even SATA SSDs noticeably cut power costs. Hard drives still make sense for bulk video storage, where cost per terabyte matters most.

PROXMOX HOST (ON DEMAND)

A custom-built PC running the Proxmox Type-1 hypervisor hosts services that only need to run some of the time, plus any VMs I spin up to develop and test new ideas. It stays powered off until I need it. Each VM and its allocated resources:

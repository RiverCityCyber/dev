Project O.D.A.S.H.I.

Onboard Diagnostics Assistant Serving Helpful Information

OVERVIEW

O.D.A.S.H.I. is a Raspberry Pi 5 head unit that replaces the factory navigation screen in my 2005 Acura MDX. It runs Apple CarPlay and overlays live vehicle data on screen: engine readings over OBD-II, tire pressures read straight from the 315 MHz TPMS sensors, and the Pi's own health. A dashcam and a voice assistant come later.

Before I write any vehicle code, I bench test the whole system on a 12V bench supply, wired the same way it will be in the car. That way each stage I install leaves the car drivable.

STATUS: In progress — CarPlay running on the Pi, building the 12V test bench. Updated November 2026.

ENGINEERING NOTES

  • K-line, not CAN. I planned the project around CAN-Bus, but checking the OBD-II port with a multimeter showed pin 7 at about 6V and pins 6 and 14 at 0V. That means the MDX only speaks ISO 9141-2 K-line, so I changed the adapter choice and the data plan.
  • Switched from react-carplay to LIVI. LIVI takes telemetry from any process on the Pi over a local HTTP endpoint, so my sensor code lives outside LIVI. That keeps my changes to LIVI small and makes upstream updates easy to merge.
  • Power is the hard part. The Pi runs off a fused constant 12V feed through the CarPiHAT, which senses the ignition so the Pi can shut down cleanly. The display runs off the accessory circuit through its own fused 12V→5V buck converter.
  • The display must be readable in sunlight. Typical Pi screens are unreadable in direct Florida sun, so screen brightness decided which display I bought.

TELEMETRY PIPELINE

Small sender programs read each data source and POST JSON to LIVI, which renders it on the dashboard: 

curl -d '{"coolantC":88,"tirePressure":{"frontLeftKpa":241}}' \
  http://localhost:4000/telemetry

LIVI already has fields for coolant, oil, transmission and intake temperatures, throttle, battery voltage and all four tire pressures. Engine load and the Pi's own stats need new fields, which I'm adding in LIVI's Rust telemetry model and Slint dashboard.

ROADMAP

  • Disconnect the factory navigation system
  • Choose a sunlight-readable touchscreen
  • Install LIVI on the Pi and flash the CarPlay dongle
  • Build the 12V test bench (fuse, CarPiHAT, buck converter, display)
  • Phase 1: boot-time sender for Pi temperature, CPU and RAM, with a new LIVI dashboard panel
  • Phase 2: K-line OBD-II adapter, then coolant, RPM, speed, throttle, engine load and voltage
  • Phase 3: tire pressures via RTL-SDR + rtl_433
  • Transmission temperature via a thermistor and an ADS1115 ADC
  • Dashcam, steering-wheel buttons and an onboard voice assistant

BUILD YOUR OWN PI DASH-CAM

  1. Install Raspberry Pi OS Lite (or distro of choice) on a Raspberry Pi
  2. Connect USB camera of choice (I am using a Logitech Webcam)
  3. Update the system (sudo apt update && sudo apt upgrade)
  4. Run the following to show your webcam's information 
    v4l2-ctl --list-devices
  5. Create the following script in /usr/local/bin/ 
    #!/bin/bash
cd /home/pi/videos
find /home/pi/videos -type f -name "*.mjpeg" -mtime +14 -delete

ffmpeg -f v4l2 -input_format mjpeg -video_size 1280x720 -framerate 30 \
  -i /dev/video0 -c:v copy -f segment -segment_time 60 \
  -segment_atclocktime 1 -strftime 1 "dashcam_%Y%m%d_%H%M%S.mjpeg"
  6. Set the script to run on startup

You now have a working dashcam that records whenever it is running and stores the video locally.
